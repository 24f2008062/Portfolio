# Phase 1 Plan 01-01: Install R3F + drei, Canvas Wrapper, Basic Scene

**Phase:** 1 (01-foundation)
**Plan:** 01-01
**Status:** Pending
**Requirements:** FND-01, FND-04

## Objective

Install React Three Fiber, drei, and Three.js dependencies. Create the Canvas wrapper component with Suspense and ErrorBoundary. Mount a minimal scene (empty `<group />`) in the Hero section. Verify bundle size baseline.

---

## Tasks

### Task 1: Install 3D Dependencies
- **ID:** 01-01-01
- **Description:** Install `@react-three/fiber`, `@react-three/drei`, and `three` as production dependencies
- **Files Modified:** `package.json`, `package-lock.json`
- **Read First:** `package.json`
- **Acceptance Criteria:**
  - `npm install @react-three/fiber @react-three/drei three` completes without peer dependency errors
  - All three packages listed in `dependencies` (not devDependencies)
  - Versions compatible with React 19 (R3F v9+, drei latest)
  - `npm ls @react-three/fiber @react-three/drei three` shows no extraneous/missing deps

### Task 2: Create Canvas Wrapper Component
- **ID:** 01-01-02
- **Description:** Create `src/components/three/Canvas3D.jsx` with Canvas, Suspense, ErrorBoundary
- **Files Modified:** `src/components/three/Canvas3D.jsx` (new)
- **Read First:** `src/main.jsx` (Hero component structure), `.planning/phases/01-foundation/01-CONTEXT.md`
- **Acceptance Criteria:**
  - Exports `Canvas3D` component accepting `children` prop
  - Wraps children in `<Canvas>` with `camera={{ position: [0, 0, 5], fov: 50 }}`
  - `<Suspense fallback={<CanvasFallback />}>` wraps scene content
  - `<ErrorBoundary fallback={<CanvasErrorFallback />}>` wraps Suspense
  - `CanvasFallback` renders minimal loading indicator (spinner or "Loading 3D...")
  - `CanvasErrorFallback` renders the static terminal panel fallback
  - Canvas style: `position: absolute; inset: 0; width: 100%; height: 100%; z-index: -1;`
  - No hardcoded dimensions — fills parent container

### Task 3: Create Basic Scene Component
- **ID:** 01-01-03
- **Description:** Create `src/components/three/HeroScene.jsx` with empty group placeholder
- **Files Modified:** `src/components/three/HeroScene.jsx` (new)
- **Read First:** `.planning/phases/01-foundation/01-CONTEXT.md`
- **Acceptance Criteria:**
  - Exports `HeroScene` component
  - Returns `<group />` (empty Three.js group — placeholder for Phase 2 content)
  - No props, no side effects, no useFrame
  - Tree-shakeable: no drei imports unless needed

### Task 4: Create ThreeD Context Provider
- **ID:** 01-01-04
- **Description:** Create `src/context/ThreeDContext.jsx` with `ThreeDProvider` and `useThreeD()` hook
- **Files Modified:** `src/context/ThreeDContext.jsx` (new)
- **Read First:** `.planning/phases/01-foundation/01-CONTEXT.md` (Decision 4)
- **Acceptance Criteria:**
  - Exports `ThreeDProvider` and `useThreeD()`
  - Context value: `{ shouldRender3D: boolean, webglSupported: boolean, prefersReducedMotion: boolean }`
  - Provider runs WebGL detection + reduced-motion check on mount
  - Memoized context value to prevent unnecessary re-renders
  - Wraps entire App in `main.jsx` (or Page-level for future 3D components)

### Task 5: Extract TerminalPanel Component
- **ID:** 01-01-05
- **Description:** Extract terminal panel from Hero into `src/components/hero/TerminalPanel.jsx`
- **Files Modified:** `src/components/hero/TerminalPanel.jsx` (new), `src/main.jsx` (Hero component)
- **Read First:** `src/main.jsx` lines 229-255
- **Acceptance Criteria:**
  - `TerminalPanel` component renders exact same HTML as current `.terminal-panel` aside
  - Accepts no props (static content for now)
  - Used by both Hero (when 3D enabled) and Fallback3D (when 3D disabled)
  - No visual difference between original and extracted component

### Task 6: Integrate Canvas3D into Hero
- **ID:** 01-01-06
- **Description:** Modify Hero to render Canvas3D behind terminal panel when 3D enabled
- **Files Modified:** `src/main.jsx` (Hero component), `src/components/three/Canvas3D.jsx`
- **Read First:** `src/main.jsx` Hero component (lines 202-257), `src/components/three/Canvas3D.jsx`
- **Acceptance Criteria:**
  - Hero renders `<Canvas3D><HeroScene /></Canvas3D>` when `useThreeD().shouldRender3D === true`
  - Canvas positioned absolutely behind hero content (`z-index: -1`)
  - TerminalPanel remains in foreground (existing layout unchanged)
  - When 3D disabled: Hero renders TerminalPanel only (handled by Canvas3D ErrorBoundary/Fallback)
  - No layout shift between 3D and fallback modes

### Task 7: Add Bundle Analysis Script
- **ID:** 01-01-07
- **Description:** Add `rollup-plugin-visualizer` to vite config, create bundle check script
- **Files Modified:** `vite.config.js` (new), `package.json`, `scripts/check-bundle-size.js` (new)
- **Read First:** `package.json`, `vite.config.js` (if exists)
- **Acceptance Criteria:**
  - `vite.config.js` exports config with `visualizer()` plugin (output: `dist/stats.html`)
  - `package.json` scripts: `"build": "vite build"`, `"check:bundle": "node scripts/check-bundle-size.js"`
  - `scripts/check-bundle-size.js`:
    - Reads `dist/stats.html` or analyzes `dist` output
    - Computes gzipped size of `@react-three/fiber`, `@react-three/drei`, `three`
    - Exits non-zero if 3D deps > 200KB gzipped OR total JS > 500KB gzipped
    - Logs: `3D deps: XX KB (limit: 200 KB)`, `Total JS: XX KB (limit: 500 KB)`
  - `npm run build && npm run check:bundle` passes on initial install
